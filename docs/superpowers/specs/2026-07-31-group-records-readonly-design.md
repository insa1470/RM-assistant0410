# 同組完整訪談紀錄查閱設計

## 背景

RM 隨行助手目前已累積較多訪談、現場與會議紀錄。管理後台可以看全部資料，但一般同仁沒有安全且清楚的方式查閱同組過去紀錄。下一階段目標是讓資料從「填報」進一步變成「組內知識庫」，先支援同組同仁查閱完整訪談內容。

## 第一版範圍

第一版只開放同組查閱下列紀錄：

- 訪談紀錄：`type = report`
- 現場紀錄：`type = site`

第一版不開放：

- 會議紀錄：`type = meeting`
- 跨組查閱
- 全行公開查閱
- 修改、刪除、覆蓋別人的紀錄
- 未填 `rm_group` 的紀錄
- 非管理八組資料：`197`、`198`、`300` 等

管理八組固定為：

`301, 302, 303, 305, 306, 321, 322, 323`

## 權限設計

因為目前小程式沒有帳號登入，不能只靠使用者輸入姓名或 RM 組別判斷權限。第一版使用「組別通行碼」。

流程：

1. 使用者進入「本組紀錄」。
2. 選擇 RM 組別。
3. 輸入該組通行碼。
4. 驗證通過後，前端保存該組短期授權狀態。
5. 查詢紀錄時，後端只回傳該組 `report` 與 `site` 的完整資料。

安全原則：

- 組別通行碼不能等同後台管理員密碼。
- API 必須在後端驗證通行碼，不能只在前端判斷。
- 查詢 API 必須固定限制 `rm_group = 已驗證組別`。
- 查詢 API 必須固定限制 `type IN ('report','site')`。
- 同組紀錄只讀，不提供修改或刪除接口。

## 資料儲存

新增一個簡單的組別通行碼資料表或等價儲存：

- `rm_group`: 組別
- `passcode_hash`: 通行碼雜湊
- `updated_at`: 更新時間

不儲存明文通行碼。

後台提供通行碼重設功能：

- 管理員可針對八個管理組重設通行碼。
- 重設後顯示一次新通行碼，後續不顯示明文。
- 若尚未設定通行碼，該組不能使用「本組紀錄」。

## 前端畫面

在使用者端紀錄相關區域新增切換：

`我的紀錄 | 本組紀錄`

本組紀錄畫面分兩個狀態：

1. 未驗證狀態
   - 選擇 RM 組別
   - 輸入組別通行碼
   - 驗證按鈕

2. 已驗證狀態
   - 顯示該組完整訪談與現場紀錄
   - 支援搜尋公司名稱、填寫人、地點、日期
   - 支援篩選 8+E、環金陸企、業務標籤
   - 點選單筆紀錄後顯示完整內容

手機畫面要求：

- 不新增複雜側欄。
- 搜尋與篩選以緊湊控件呈現。
- 紀錄列表保持現有卡片風格。
- 詳情頁沿用既有紀錄詳情呈現方式，避免破壞現有版面。

## API 設計

新增或擴充 API：

1. 驗證組別通行碼

`POST /api/group-auth`

輸入：

- `rmGroup`
- `passcode`

輸出：

- 驗證成功：短期 token 或一次性 session key
- 驗證失敗：錯誤訊息

2. 查詢本組紀錄

`GET /api/group-records`

輸入：

- `rmGroup`
- `token`
- 搜尋條件：關鍵字、日期、標籤

後端固定限制：

- `rm_group = rmGroup`
- `type IN ('report','site')`
- `rm_group IN ('301','302','303','305','306','321','322','323')`

3. 後台重設通行碼

`POST /api/admin/group-passcode`

輸入：

- 管理員密碼
- `rmGroup`
- 新通行碼，或由後端生成

輸出：

- 重設成功
- 若由後端生成，回傳一次性明文通行碼

## 錯誤處理

- 組別不在八組內：顯示「此組別未開放本組紀錄」。
- 通行碼錯誤：顯示「組別通行碼錯誤」。
- 未設定通行碼：顯示「此組尚未設定通行碼，請洽管理員」。
- Token 過期：要求重新輸入通行碼。
- 查無資料：顯示「本組目前沒有符合條件的紀錄」。

## 測試重點

- 未驗證不能查詢本組紀錄。
- 301 通行碼不能查到 302 資料。
- 本組紀錄不包含 meeting。
- 本組紀錄不包含未填組別資料。
- 本組紀錄不包含 197、198、300 等非管理組。
- 同組紀錄 API 不提供修改與刪除。
- 後台管理員仍可看全部資料。
- 既有新增訪談、匯出、後台統計、明細紀錄功能不受影響。

## 分階段落地

第一階段：

- 建立通行碼儲存與後台重設。
- 建立本組紀錄驗證與查詢 API。
- 使用者端新增本組紀錄入口與完整只讀詳情。
- 只納入 `report` 與 `site`。

第二階段：

- 會議紀錄新增組別欄位或自動帶入組別。
- 評估是否把同組會議紀錄納入本組紀錄。

第三階段：

- 若需要，再設計跨組共享或全行公開標記。
